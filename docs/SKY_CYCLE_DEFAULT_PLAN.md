## 2. Target design

Mapping (enum ints and wire format unchanged; RANDOM keeps `sky_theme_resolved` in {sunset, night, dawn}):
- `CYCLE`: running cycle, the NEW DEFAULT (`MatchConfig.sky_theme_mode = CYCLE`). Starts at `SkyThemeDef.cycle_start_phase` (default 0.10: morning, sun ~38 deg, fully day) via the existing phase offset, so every peer opens identically.
- `DAY` -> "Sunset": cycle locked at `cycle_locked_phase_sunset` (0.47, sun ~12 deg on the setting side). `DAWN`: locked at `cycle_locked_phase_dawn` (0.03). `NIGHT`: locked at `cycle_locked_phase_night` (0.75, midnight). `RANDOM`: host rolls one of those three (unchanged `SKY_THEME_IDS`/`resolve_sky_theme`), never the running cycle (owner wording). All values are `SkyThemeDef` exports (tunable, tuning-panel hints required: `test_tuning_panel.gd:962`), tuned by capture, not guessed.
- Locked = the same cycle code with the clock ignored: `cycle_phase_at()` returns the locked phase. Storm blend, weather, ambient life, flare and puffs all keep working (they already compose on `_cycle_theme`). A locked cycle writes the sky once (set `Sky.PROCESS_MODE_QUALITY` after the one update, `refresh_reflection_capture()`), so default matches do not pay incremental radiance every frame (perf sample is acceptance).
- Network: the locked phase is derived from `sky_theme_mode` + `sky_theme_resolved` (already replicated) and shipped `SkyThemeDef` content; it needs no clock and no new wire field. The running cycle keeps `SnapshotSync.sky_cycle_seconds()`. F4 lock edits are local dev tuning, like `cycle_length_seconds` (`SkyThemeDef.gd:3-8`).
- Day palette (DECISION, flagged for owner review of captures): the owner prefers Dawn over Sunset, and a Cycle opening in the sunset palette would lose that look. The cycle's day half blends the `dawn.tres` palette (morning/noon) into the `sunset.tres` palette on the setting side by `dusk_w = smoothstep(a,b,phase) * (1 - smoothstep(c,d,phase))`, `(a,b,c,d) = cycle_dusk_weight_phases` (default 0.30, 0.46, 0.90, 0.98); the structure (shader materials, ambient life, cycle_* fields) stays the `sunset.tres` duplicate. Locked Dawn therefore looks like today's Dawn; locked Sunset like today's procedural sunset palette.
- Panorama removal (P6 of `docs/SKY_PROCEDURAL_PLAN.md`): every theme runs the procedural branch (`sky_look_procedural = true`, mix 1) then the `panorama` uniform, `sample_panorama`, sway/warp/sea-flow code, `sky_panorama_uv`, `panorama_lod`, the puff far-fade tap and the night sea tap are deleted, then `assets/sky/sunset-clouds-v1.png`. DECISION: keep the `sky_look_procedural` / `procedural_sea_mix` fields (removing them forces Skybox/TuningPanel/storm-blend edits); cleanup follow-up bead. `night.tres`/`dawn.tres`/`storm.tres` stay as data sources (cycle night palette, dawn palette, storm blend target).
- Lobby labels (DECISION): keep index order so enum ints and `test_lobby.gd` stay valid; relabel "Day" -> "Sunset"; Cycle is preselected through the new default. F4: Theme dropdown gets a leading "cycle" entry (`Skybox.start_cycle()`; persisted as `skybox_config.theme_name = "cycle"`, handled in `Skybox._ready`), plus a Sky-tab "Time of day" row: OptionButton (Running / Sunset / Dawn / Night / Custom) and a 0..1 phase slider enabled for Custom -> `Skybox.set_locked_phase()`; the existing cycle-length slider then works with Running. Live slider edits in cycle mode call `refresh_cycle_sources()` instead of `apply_theme`.

## 5. Root-cause hypotheses (verify with the first step of each package)

- **mp0.93 underside artifacts** (screenshots `_181937`, `_181816`: huge flat lavender slabs with razor-flat horizontal bottoms, white hairlines, jagged shards; flat blue-lavender matches `puff_floor_tint (0.42,0.5,0.68)`).
  H1 (primary): the always-on UpperPuffs layer has flat bases at `height_m = 96 m` (`config/WeatherCeilingTuning.gd:11`, `vfx/CloudSea.gd:334-355`, bases 96..120 m, radius 50..110 m) while the gameplay camera sits at/below ~70-100 m, so the flat base plane is seen edge-on or from below: base clipped by `entry.y < -flat_base` (`shaders/cloud_puffs.gdshader:286`), widened base polygon (`:217-219`), and on the upper layer the brightness floor `col = max(col, tone_floor * floor_on)` (`:353-354`) turns the whole shadowed underside into one flat tint, so the cel bands vanish and the slab edge reads as a cut. H2: `edge_soft_px` soft edges (alpha < 1, `:277-281`) in the transparent pass write depth (`depth_draw_always`) and MultiMesh instances are unsorted, so a soft base edge can punch hairline holes in puffs drawn after it (jagged white lines). H3: cellular-noise dome creases on the base (`lumps` on `unit` for `on_base`) alias. Candidate fixes (B1 picks after the capture): a gradient base ramp instead of the floor clamp, `underside` darkening kept under the floor, dither-fading base fragments by camera height clearance, round the base (small `flat_base` on the upper layer), raise/offset `height_m`.
- **mp0.94 storm rays**: `sun_effect_scale` (`core/CloudLighting.gd:112`, `Skybox.gd:1084-1107`) leaves 3% (`sun_storm_attenuation = 0.97`) x overcast keep 0.4 at full storm (about 1%), and `ray_intensity`/`ray_color` are not part of the storm blend (`Skybox.gd:803-831` blends only colours/`proc_*`; `storm.tres` sets `ray_intensity = 0` but it is never applied). The sun DISC fades by the unrelated linear `proc_sun_glow_strength` lerp, and clouds hide only the disc because rays live in the sky pass (`sunset_clouds.gdshader:424-439`, 55 deg reach) behind every puff. So rays can outlast a "hidden" sun at intermediate intensity or whenever puffs, not the storm blend, hide it. Secondary: `SunFlare.set_cycle_sun` (`:143`) re-enables the flare each phase tick and `set_theme_enabled` (`:131`) resets/duplicates its config (`Skybox.gd:315-322` re-disables it afterwards, so only order-sensitive). Not reproducible by reading alone: SUN1's first unit test must find which term is nonzero. Fix direction: one `sun_visibility` factor (hard zero above a `storm_sun_off_amount`, overcast-aware) multiplying disc, halo, rays and flare.
- **mp0.95 sun through arena/clouds** (`_183854`: starburst + ghost ring drawn over the disc underside). Cause 1 (hard evidence): `SunFlare._occlusion_factor` (`vfx/SunFlare.gd:297-306`) is one physics ray, but the disc collider is a single-sided trimesh (`game/Field.gd:661-670`: `backface_collision = false`, faces only up/out of the rim), so a camera below the disc shoots through it unhit. Fix: also cast the reverse ray (sun point -> camera; hits the front faces) and treat either hit as occluded. Cause 2: puffs are not physics bodies, and the flare is an additive canvas layer (`FLARE_LAYER = -1`) over all 3D, so clouds never hide it although the sky-pass sun disc is correctly hidden by their depth. Fix chosen: CPU occlusion estimate from per-clump bounding spheres with the orbit rotation applied, refreshed at a low rate (config) and smoothed by the existing `visibility_lerp_speed`; unit-testable headless. Rejected: depth-tested spatial flare (puffs draw in the transparent pass, absent from the depth texture; ghost rings away from the sun would still show; not testable headless).
- **mp0.92 cloud motion**: the puffs' only motion is an orbit around the disc axis, `rot2(TIME * INSTANCE_CUSTOM.x)` (`cloud_puffs.gdshader` vertex), `angular_speed = speed / ring_radius` with one speed range for all layers (`CloudSea.gd:424-425`): no layer/height parallax and a direction that disagrees with the sky-shader layers, which scroll in fixed world directions (`cloud_wind`, `proc_sea_wind`, `proc_strata2_wind` deliberately opposite, `proc_cards_wind`) with `TIME`; storm wind (`StormPresentation.heading()`, `core/WindField.gd`) reaches none of them. Design: one wind vector (calm heading from `config/cloud_wind.tres`, storm heading and gust from `WindField`) blended by the storm amount (`Skybox._storm_amount`); per-layer speed factors (nearer/higher layers faster: upper puffs > banks > sea > far ring, sky strata/cards likewise); CPU-integrated accumulators replace `TIME` in the shaders (`drift_phase` for the orbit at `1 - storm`, `wind_offset` metres at `storm`, plus per-layer sky scroll vec2s) so heading or storm changes never pop. Storm translation wraps on a torus past each layer's fade distance; DECISION: a wrap tear is accepted beyond the distance fade (shrink puffs near the wrap edge if visible). Cosmetic only: seed/event/heading agree across peers; accumulated offsets need not.
