## 3. Component API (ui/components/)
Rules for all: `class_name Ui<Name>`; styled only from `ArcadeVisualTuning` plus a new `ComponentMetrics` Resource (`config/ComponentMetrics.gd`, `config/component_metrics.tres`; no literals in scripts). Colours and radii are never passed in by screens; screens pass semantic variants (enums). Typed everything; signals not Callables.

### 3.1 Shared base: RowItem contract (`UiRowItem.gd`, static + group)
Godot cannot multi-inherit Button/Container, so the base is a contract applied in every row-capable component's `_init`:
- `UiRowItem.apply(control: Control, kind: UiRowItem.Kind, fill: bool = false)` sets `custom_minimum_size.y = metrics.row_height_px` (one value, replaces LobbyLayoutTuning row_control_height_px 36 / seat_control_height_px 32), `size_flags_vertical = SHRINK_CENTER`, `size_flags_horizontal = SHRINK_BEGIN` (or EXPAND_FILL only when `fill`), min width per kind from `ComponentMetrics` (square icon = row_height; stepper = N x row_height; badge min width), and adds group `ui_row_item`.
- `Kind { BUTTON_SM, ICON, TOGGLE, STEPPER, DROPDOWN, BADGE, METER }`.
- Rows: `UiRow extends HBoxContainer` (`separation = space_2`, label column width from metrics, optional `value_cell`). A screen builds `UiRow.new().setup(label, control)`; replaces Lobby `_align_row_controls` (Lobby.gd:697), VALUE_SPACER logic and Options per-row label fixes. Test: every `ui_row_item` in a row reports identical `size.y`.

## 4. Layout rules (fixes "stretched to fill rows", title alignment)
- Spacing scale = tokens only: space_1 4, space_2 8 (row item gap), space_3 12 (between rows), space_4 16, space_5 24 (panel padding), space_7 48 (menu edge). No other gaps; `row_separation_px 12`/`row_spacing_px 8` in LobbyLayoutTuning are removed in favour of these tokens.
- Row = label column (fixed, from metrics) + control column. Controls size to content or their metric width and align to the column start; only meters/fields/dropdowns marked `fill` may expand; toggles, steppers, badges, icon buttons never expand. Default `size_flags_horizontal` of every component is SHRINK_BEGIN.
- Hierarchy: Panel heading (heading 24/800 uppercase + flare bullet) > Section/.sa-group header (label 13/800 rim or dust) > row label (body) > caption (dust). One flare primary per screen.
- Title alignment: every screen title row uses `UiPanel` heading; the Lobby title row (title left, UiStatusBadge, Back right) aligns its left edge to the Panel's inner padding (space_5) and baseline to the badge. One `UiTitleRow` helper (in UiPanel.gd) owns it.
- Options: `UiTabs` HORIZONTAL (owner override of the side-tab form in components.md; the "top tabs" visual form with rim notch applies), tab labels GAME, GRAPHICS, CONTROLS ("Settings" renamed "Game"); LB/RB cycles.

## 7. Decisions and risks
- DECISION: Options tabs horizontal (owner request) although components.md specifies side tabs for Options; revisit if the design system source changes.
- DECISION: row height is one metric (default = existing row_control_height_px 36); seat rows adopt it (grow from 32).
- DECISION: ReadyPill from wt/loading-screen is rebased into UiStatusBadge; C1a must land after or merge-check against that branch (conflict risk in ui/LoadingScreen.gd, ui/lobby/LobbySeatRow.gd).
- Risk: Lobby.gd (1861 lines) and tests rely on node unique names (%SuddenDeathCheck etc.); migration keeps names by replacing scene nodes in place and exposing the same signals. Remote `_apply_data()` and read-only client sync call `.button_pressed`/`.value`; UiToggle/UiStepper provide `button_pressed`-compatible `set_on`/`value` and `set_value_silent` to avoid feedback loops.
- Risk: 1pi.153 and 159.3 touch OptionsMenu; serialise.
- No gameplay or [ORIGINAL] rule change; no owner question needed.
