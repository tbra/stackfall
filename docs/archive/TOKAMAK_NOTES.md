# Tokamak 1.0.5 notes: what the original did, and what maps to Jolt (Bontago-1pi.11.12)

Source read: `M:/Bontago/feedback/tokamak_release/tokamaksrc/src/` (gitignored, BSD/Zlib). Line numbers are into that tree. Nothing is copied here; this is behaviour only. Not verified by running anything; the game's own step size and materials are not in the library (the app chose them), so those are unknown.

## 1. Idle/asleep and anti-creep

Status enum has `NE_RBSTATUS_IDLE` (rigidbody.h:517). A body is per-body, but the decision depends on its rest contacts.

- Low-energy counter: `CheckForIdleNonJoint` (restcontact.cpp:104-178). Each step, `|v|^2 < highEnergy` AND `|w|^2 < highEnergy` (`NE_HIGH_ENERGY = 1.0`, simulator.cpp:39,134) increments `lowEnergyCounter`. So the test is on SQUARED speed: about 1 m/s and 1 rad/s, i.e. enormously looser than Jolt's 0.03 m/s. If over threshold it still counts as low-energy when the 10-step average velocity (gravity component removed) has `v^2 <= 2` and average angular `w^2 <= 1` (restcontact.cpp:118-165).
- Sleep trigger: `lowEnergyCounter > 10` (about 10 steps) and the body has a valid rest hull (`stackInfo && IsRestPointStillValid()`, `CheckRestHull`). Hull = 3+ support points: idle immediately. Hull = 2 points (an edge): only after `lowEnergyCounter > 100`. Hull = 1 point or none: never (restcontact.cpp:166-177). Support polygon test: projected contact point within 0.005 m of the centre line/point (restcontact.cpp:300-331). Gravity-facing contacts invalidate rest records (restcontact.cpp:413-420).
- `BecomeIdle()` zeroes all velocity history and momentum (rigidbody.cpp:797-820). This is the anti-creep: sleeping snaps velocity to exactly 0.
- Idle body cost: `AdvanceDynamic` returns early if `CheckStillIdle()` (rigidbody.cpp:448-453; restcontact.cpp:342-366): stays idle while energy < `highEnergy` and the rest hull is still valid. Idle bodies are skipped for collision detection: pairs are only processed if at least one is non-idle/shifted/moved (simulator.cpp:1116, 1172, 1233-1242).
- Wake: nonzero `cforce`/`ctorque` (rigidbody.cpp:439-446); energy over `highEnergy` (restcontact.cpp:344-360); a moving partner (`CanConsiderOtherBodyIdle`, rigidbody.cpp:1089-1107; rest on world counts as idle). A colliding non-resting hit on an idle body with `e > highEnergy` gets a full shift and wakes, else the idle body is left alone and the other body is pushed out by the penetration depth (simulator.cpp:1776-1806). So settled blocks are treated as quasi-static, immovable terrain against gentle contact.
- Stack/tower level: rest records (max 3 per body, `NE_RB_MAX_RESTON_RECORDS`, rigidbody.h:480) link each body to what it rests on; `stack.cpp` groups them into stack headers (`neStackHeader`, `isAllIdle` stack.h:67). `neStackHeader::Resolve` (stack.cpp:205-243) walks the stack once and removes penetration bottom-up (`neStackInfo::Resolve`, stack.cpp:67) instead of iterating a global solver. `CheckContactValidity` short-circuits when the body and all its supports are idle (restcontact.cpp:370-400) - a settled tower does essentially no work.
- Other creep control: `CheckStationary` (restcontact.cpp:835+) - after 60 steps, compares position to a stored `oldPosition`; speed under `sleepingParam` 0.2 (rigidbody.cpp:154) plus loose accel limits (5 / 10 / 10.5) counts as stationary. Default damping is zero (`linearDamp = angularDamp = 0`, rigidbody.cpp:150-152); there is no damping-based stabilisation.

## 2. Solver and why it is cheap

- Fixed constant iteration count: `DEFAULT_CONSTRAINT_ITERATION 4` (simulator.h:19), epsilon `0.001` (simulator.h:17), used at solver.cpp:1691-1723. Two stages: pp=0 friction stage, pp=1 penetration stage, each looping `iteration` times (solver.cpp:1735+). A sleep check runs at half the iterations (`checkSleep = iteration >> 1`, solver.cpp:1731) and `CheckIfStationary()` after each chain (solver.cpp:1701). That is 4+4 sweeps vs Stackfall's Jolt `velocity_steps = 192`.
- Time step: `Advance(sec, minTimeStep, maxTimeStep)` loops fixed sub-steps with variable step clamped to +/-20% of the previous one (`frameDiffTolerance 0.2`, simulator.cpp:760-820). Caller chooses the step; the library has no fixed default.
- Penetration: no Baumgarte bias. Contacts are resolved positionally: `SimpleShift` moves bodies apart by depth (simulator.cpp:1776-1830), idle bodies are preferentially not moved, then an impulse is applied (`HandleCollision ... IMPULSE_NORMAL`, scale 1.0). Resting contacts are cached as body-local rest records (`neRestRecord`, stack.cpp:36-65) and updated by transforming the points each step, not re-detected.
- Materials default friction 0.5 (simulator.cpp:73); restitution/density per material via `SetMaterial` (simulator.cpp:290).
- Cost levers: idle bodies skipped in integration, broadphase/narrowphase and solver (above); stacks solved as chains only when any member is awake (`allIdle` checks in solver.cpp around 1650-1690); rest records avoid re-collision; tiny iteration count. A settled 300-block field costs roughly the idle check per body.

What it gave up: stability is weak-physics stability. It is sleep-forcing and position-shifting, not accurate resting contact; the original's towers felt solid partly because bodies snapped to zero velocity very early and were then treated as static.

## 3. Mapping to Jolt / Godot 4.7

Current Stackfall (tools/bootstrap_project.gd:91-111): `velocity_steps=192`, `position_steps=4`, `body_pair_contact_cache_distance_threshold=0.0001`, `sleep_time_threshold=0.5`, `sleep_velocity_threshold` left at Godot default 0.03 m/s. Block damp 0.1 / 0.15 (config/PhysicsTuning.gd), friction 0.85, bounce 0.4. `StableBlockManager` freezes to static only after 20 s asleep (config/physics_tuning.tres `stable_freeze_delay_s`), so a creeping block never reaches it.

| # | Change | Where | (a) b0w creep | (b) awake-pile CPU (bth) | (c) feel risk |
|---|---|---|---|---|---|
| 1 | `sleep_velocity_threshold` 0.03 -> 0.08-0.15 (try 0.05, 0.1). Tokamak is ~1 m/s squared; we need only the creep band (1 mm/s) | bootstrap_project.gd | Fixes it: creep 1 mm/s is well below; sphere = threshold*dt per sleep window | Fewer awake bodies after a hit; islands sleep sooner | Low-medium. Blocks "freeze" mid-wobble if too high (0.15 visibly stops slow topples). Needs owner playtest above 0.1 |
| 2 | `sleep_time_threshold` 0.5 -> 0.25-0.3 | bootstrap_project.gd | Helps little alone | Piles sleep sooner | Low; but spec 3.5 says 0.5 - is that [ORIGINAL]? Do not change without checking spec tag |

All gameplay-feel items (#1 above 0.1, #3, #4) need an owner playtest; none of this touches an [ORIGINAL] rule as written, but #2 should be checked against spec 3.5 text, and spec 2.2's settled rule (0.15 m/s, 0.3 rad/s, 0.5 s) is the natural threshold pair for #3.

Caveat from the Bead history: Bontago-bth attribution (1pi.11 comments, batch 5) found the awake-pile cost is GPU/render-side, headless physics <= 0.24 ms at 300 blocks. So #1/#3/#4 mainly fix sleeping (b0w, AI/network snapshot traffic, StableBlockManager coverage) and only bear on CPU when many blocks are awake. Do not expect a frame-time win from physics changes alone.

## 4. Ranked packages

1. **P1 sleep threshold sweep** (files: tools/bootstrap_project.gd, project.godot (generated), tests/bench/bench_physical_balance.gd only if needed). Sweep `sleep_velocity_threshold` in {0.03,0.05,0.08,0.1} with serialized benches. Accept: bench_physical_balance `all_asleep=true`, bench_tower still 8/8 clean with drift <= 0.03 m, bench_perf_attrib awake count after settle (report) lower, no new GUT failures in test_tower_placement. Smallest change; closes b0w if it passes. Owner playtest for the chosen value.
2. **P2 settle pass in StableBlockManager** (files: game/StableBlockManager.gd, config/PhysicsTuning.gd, config/physics_tuning.tres, game/Block.gd, tests/unit/test_stable_block_manager.gd, tools/bench_perf_attrib.gd for a `--settle` report). Optional: zero velocity + sleep a supported block once under spec 2.2 thresholds for `settle_freeze_s` (e.g. 1.5 s). Accept: leaned-disc bench awake count 0 within 5 s; toppling tower bench (bench_tower with an off-centre drop) still collapses; `--churn=6 --rest --spikes` physics step ms at 300 blocks not worse, awake count after settle reported; unit test for wake on impulse and on neighbour removal.
3. **P3 velocity_steps reduction study** (files: tools/bootstrap_project.gd, bench files). Only after P1/P2. Sweep 192/128/96/64; accept only if bench_tower 8/8 and physical_balance pass and step ms at 300 blocks drops measurably with `--churn`. Probably reject if the 40-tower needs 100+ (recorded already in bootstrap comments).
4. **P4 (optional) support-hull gating**: use contact-count via `get_colliding_bodies` or Jolt contact report to allow P2 only for blocks with >= 3 support points or a settled supporter (mirrors restcontact.cpp:166-177). Files: game/StableBlockManager.gd, game/Block.gd, tests.

Out of scope: swapping to a Tokamak-style positional solver; anything altering rule-tagged [ORIGINAL] behaviour; P2's freeze delay and P1/P3 values are feel questions for the owner, not rule changes.
