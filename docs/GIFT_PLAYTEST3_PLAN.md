## 1. Code anchors (what exists today)

- In place: `SpecialDef.activates_in_place` (config/specials/SpecialDef.gd), `MatchGiftActivation.try_activate` (autoload/match/MatchGiftActivation.gd): builds an invisible frozen anchor `Block` (never registered, no net_id), arms `SpecialBehavior`, calls `behavior.advance(0.0)`; the effect reaches clients only through `Events.special_triggered` with `IN_PLACE_NET_ID`, routed by `GiftFxPresenter.on_special_triggered` (game/specials/fx/GiftFxPresenter.gd) to per-id builders. Volcano is the template: `VolcanoEffect.detonate` spawns a `VolcanoStructure` (host, physics) and `_build_volcano` -> `VolcanoStructure.build_client_visual` (clients). `SpecialBehavior.advance` ignores `needs_landing` when `activates_in_place` (:138-139), so `behavior.landed_age()` is NOT available to an in-place effect (never landed).
- Propeller: `PropellerEffect` (needs_landing, `physics_tick` runs `DiscForce.apply(-1)` for `disc_force.duration_s`, visual rise only on the carrier's GiftVisual via `_apply_visual_rise` / `ClientRiseDriver`). With an anchor there is no GiftVisual and no landed_age, so it cannot just get the flag.
- Anvil: `AnvilEffect` (mass 60 set on first armed tick, own `LandedProbe`, `detonate` = `DiscForce.apply(+1)` at landing). Carrier is a real replicated body (scale 5x, `BlockFactory.apply_gift_visual`).
- Black hole: `BlackHoleEffect.detonate` spawns `BlackHoleField` at `block.global_position`; `GiftFxPresenter._build_black_hole` -> `BlackHoleVisual` (grows in over `grow_in_s`, tolerates a null block). The anchor Block works for it unchanged.
- Throw: `GiftAim.spawn_point(cursor, forward, surface_y, t)` = cursor - forward * `gift_aim_back_m` (8.0), clamped >= `gift_aim_min_height_m` (core/gifts/GiftAim.gd:22-29). Preview `PlayerController.gift_launch_preview` (game/PlayerController.gd:1045-1070) calls it with `_ghost.global_position`; host `MatchPlacement.request_throw` (:387-482, spawn at :482) calls the same function with the client-sent `origin` (the ghost pose). Preview is drawn by `_drive_throw_visuals` (:1020) whenever `_can_preview_gift_aim` (:1035) is true (any mode != NONE).
- Rocket facing: `RocketEffect._face_direction` (:257) writes `block.global_transform` each flight tick from `nose_basis(model_nose_axis, direction)` with `model_nose_axis = (0,1,0)` (rocket.tres); `angular_velocity` zeroed (:187). 1pi.85.25 already shipped this, yet the owner still sees a vertical rocket. `MagnetEffect` has NO facing code at all. Throw velocity for Magnet is the GiftAim arc.
- Volcano launch: `VolcanoStructure._erupt` (:327-355) spawns 1-3 blocks per burst `burst_spread_m` 0.8 apart on a phase ring but all via `_launch_velocity()` (:357): random azimuth, polar 0..`cone_angle_deg` 35, constant `launch_speed_mps` 9.0. Same speed + small spread = ejected blocks nearly collide (confirmed by the code, no per-block separation).
- Jumping Bean: `JumpingBeanEffect._kick` (:~150) picks `angle = _rng.randf_range(0, TAU)` with `hop_horizontal_speed` 7.0; tres: first delay 0.4, interval 1.0, lifetime 14.0, impulse 9.0.
- Magnet: `pull_duration_s = 3.0` (magnet.tres), `effect_lifetime_s()` = it.
- Glue: `GlueDrops.try_bond` builds a Generic6DOF `GlueJoint` with `GlueDropTuning` (config/glue_drop_tuning.tres: break_force 600, break_separation_m 0.15, break_speed_mps 6.0, break_shock_mps 2.5). The green look is `GhostPreview._apply_glue_overlay` (game/GhostPreview.gd:2049-2063; `GLUE_OVERLAY_COLOR` (0.55,0.95,0.25,0.45), roughness 0.08, rim) applied to the HELD ghost (local) and to remote ghosts via `RemoteCursors._on_glue_charges_changed` (:119). Placed glued blocks carry no visual and `GlueDrops` runs host-only (MatchPlacement.gd:350), so clients cannot see which blocks are glued today.
